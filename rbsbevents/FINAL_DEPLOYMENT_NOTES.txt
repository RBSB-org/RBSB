EVENTWALE / RBSB EVENTS — FINAL BUILD NOTES
==========================================

Included changes
----------------
1. Event Approvals now displays all booking records from the existing Firebase
   bookings/{userId}/{bookingId} collection. It uses the same live records as
   Booking Management; it does not invent or migrate a separate event collection.
2. Approve / Reject actions appear for pending records on Event Approvals and update the existing booking status. The pending badge counts only pending records; already approved/rejected decisions remain visible.
3. Booking Management now includes a Delete action for pending, approved, and
   rejected records. Deletion asks for confirmation and removes only the selected
   booking record from its existing user-specific path.
4. Theme Customizer now publishes a shared theme to Firebase at
   siteSettings/theme. It controls primary, accent, page background, card surface,
   main text, muted text, borders, website name, and the generated favicon.
5. Public pages load site-theme.js and apply the published theme in real time.
6. Existing Firebase booking flow and email.js / EmailJS files were retained.

IMPORTANT FIREBASE SETUP
------------------------
The deployed Realtime Database rules must permit public reads of the published
theme and admin-only writes. The updated example is in FIREBASE_DATABASE_RULES.json.

If your live rules are different, DO NOT replace them blindly. Merge only this
path into your existing rules:

"siteSettings": {
  "theme": {
    ".read": true,
    ".write": "auth != null && root.child('admins').child(auth.uid).val() === true"
  }
}

Publish the merged rules in Firebase Console > Realtime Database > Rules.
Keep all existing admins, bookings, events, services, venues, and locations rules.
